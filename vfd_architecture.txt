Architecture

The desired architecture is:

Blender VFD Node / Console
        ↓
    VFDManager
        ↓
   HY01D523B
        ↓
      RS-485
        ↓
   HY01D523B VFD


hy01d523b_vfd.py must contain the actual HY protocol implementation.
vfd_manager.py should contain high-level control/state/configuration only.
vfd_node.py should contain Blender properties, UI, buttons and console command parsing.

HY parameter requirement

The VFD has parameters PD000 through PD182.
We need to support:

read PD000 ... PD182
write PD000 ... PD182


The manager should expose:

read_parameter(parameter)
write_parameter(parameter, value)


The console should translate:

get PD163
read PD163
set PD163 4
write PD163 4


into manager calls.
Parameter validation should reject values outside PD000-PD182.

Important manager cleanup

The previous manager architecture was too complicated. The desired final manager should directly use:

from .hy01d523b_vfd import HY01D523B


and create:

self.vfd = HY01D523B(...)


There should NOT be:

VFDDriver
HY01D523BAdapter
driver_manager.py


The manager should be a small HY-specific high-level controller.

Connection configuration

The Blender node has:

serial_port
slave_id
baudrate


Before connecting, these values must be passed to the manager:

manager.configure_connection(
    port=self.serial_port,
    slave_id=self.slave_id,
    baudrate=self.baudrate,
    timeout=0.25,
)


Then:

manager.connect()


Do not rely only on manager defaults such as COM3 / slave 4 / 9600.

HY communication

Do NOT blindly change the low-level parameter packet format without checking the actual HY01D523B protocol and, preferably, a real response from the user's VFD.
We need to verify:

parameter read request
parameter read response length
CRC
parameter write request
write response
address handling
baud-rate setting
communication mode
The first safe diagnostic commands should be:
connect
status
get PD163
get PD164
get PD165
get PD181
get PD182


These should be used to determine the actual communication configuration and VFD information before writing parameters.

Status

Current get_local_status() is not yet a true live measurement/status query. Some fields are locally tracked/placeholders.
Do not claim that current:

current
voltage
power
fault
fault_code


are real-time VFD measurements until the HY status registers/commands are implemented and tested.
