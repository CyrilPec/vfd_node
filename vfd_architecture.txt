Previous review

The code was reviewed for correctness. Main findings:

vfd_node.py contained accidental Markdown code fences (```python and ```), making it invalid Python.
vfd_manager.py had the same Markdown-fence problem.
The manager passed a string such as "COM3" to HY01D523B, while the driver expects a serial transport object.
Commands were locally marked successful without proper VFD response validation.
running, reverse, and fault were mostly locally simulated rather than being confirmed hardware status.
Disable/disarm should stop the VFD rather than merely changing software state.
emergency_stop() is currently only a normal software STOP and must not be described as a safety-rated emergency stop.
RUN/direction sequencing was redundant.
Frequency limits should be validated consistently instead of silently clamping values.
RPM is estimated from frequency and motor ratings, not measured spindle RPM.
Parameter read/write handling needs stronger response/CRC validation.

The low-level HY01D523B command construction appeared broadly consistent with published protocol examples, including frequency scaling of Hz × 100.

The revised architecture is:

Blender VFD Node
       |
       v
VFDManager
       |
       v
HY01D523B driver
       |
       v
pyserial RS-485 transport
       |
       v
HY01D523B VFD


The revised manager creates the serial transport approximately as:

serial.Serial(
    port=self.serial_port,
    baudrate=self.baudrate,
    bytesize=serial.EIGHTBITS,
    parity=serial.PARITY_NONE,
    stopbits=serial.STOPBITS_ONE,
    timeout=self.timeout,
    write_timeout=self.timeout,
)


and injects that transport into HY01D523B.

Default communication settings:

Port: COM3
Slave ID: 4
Baud: 9600
8N1
Timeout: 0.25 s

pyserial is required.

Install:

pip install pyserial

Important limitation

The revised driver still uses locally tracked state for:

running
reverse
frequency
fault


It does NOT yet have a confirmed implementation of the actual HY01D523B status registers.

Therefore:

Running means locally tracked command state.
Estimated RPM is calculated from frequency.
Fault=False does not prove the physical VFD has no fault.
Actual spindle RPM/current/voltage/power are not currently measured.

Do NOT invent status-register behavior without confirming the exact HY01D523B protocol/firmware.
